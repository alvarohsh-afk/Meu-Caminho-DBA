🛠️ Log de Troubleshooting: Recuperação de Ambiente Oracle 21c
Este diretório registra os erros críticos enfrentados durante a configuração do ambiente de estudos Oracle e as soluções aplicadas para restabelecer a operação do banco de dados.

📋 Cenário Inicial
O banco de dados Oracle 21c (XE) apresentava falhas de conexão tanto no DBeaver quanto no Oracle SQL Developer, impedindo a execução dos laboratórios de RH.

❌ Erro 1: ORA-12514 / ORA-12560 (TNS: Protocol Adapter Error)
Sintoma: O banco de dados parecia estar "desligado" e o Listener não reconhecia o serviço XE.

Causa: O serviço do Windows responsável pela instância do Oracle estava travado ou não havia iniciado corretamente após o boot do sistema.

Solução Aplicada:

Acesso ao terminal via PowerShell (Modo Administrador).

Uso do utilitário lsnrctl status para diagnosticar o estado do Listener.

Comando de reinicialização forçada do serviço via services.msc.

Registro manual do serviço no banco através do comando:

SQL
ALTER SYSTEM REGISTER;
❌ Erro 2: ORA-02000 (Missing ALWAYS keyword / Syntax Error)
Sintoma: Erro ao tentar criar as tabelas do laboratório de RH (CREATE TABLE).

Causa: Erro de sintaxe na cláusula de identidade (IDENTIFY em vez de IDENTITY).

Solução Aplicada:

Correção da DDL para o padrão Oracle 12c+:

SQL
GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
✅ Resultados Alcançados
Estabilidade: Ambiente 100% operacional no DBeaver e SQL Developer.

Persistência de Dados: Criação e manipulação de tabelas relacionais (Departamentos e Funcionarios) com sucesso.

Consultas Avançadas: Execução de JOINs e funções de agregação (SUM, GROUP BY) para relatórios de folha de pagamento.

💡 Lição Aprendida
A administração de banco de dados exige calma para ler os códigos de erro (Logs). O sucesso da solução dependeu do uso correto de permissões de administrador no Windows e do entendimento da arquitetura do Oracle Listener.
